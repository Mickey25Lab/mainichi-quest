# マイクエ UI座標系統一設計（第2段階）

## 目的・境界

PR #159で導入した4 viewportのDOM実寸監査により、1400×1050ではBGMの表示差0px、1024×768で20.411px、768×1024で34.309px、1280×720で23.886pxを確認した。**指定CSSピクセルの一致は実際の表示寸法一致を保証しない**。

この段階は設計のみ。HTML/CSS/JavaScriptの本番動作、プレイヤー保存データ、ゲーム進行、画面位置、音声制御を変更しない。

## 既存画面の座標系（コードから確定）

| 画面 | ルートコンテナ | 現行の座標系 | 注意点 |
|---|---|---|---|
| トップ | `.start-layer` | 可変4:3ボックス内の固定px・%混在 | BGM・管理・再読み込み等の固定pxは画面縮小に追従しない |
| モード選択 | `.mode-select-stage` | 可変4:3、%と固定px混在 | 戻る判定は%だが、選択行や文字が別方式 |
| 問題 | `.play-stage` | 固定1400×1050を`--stage-scale`で縮小 | BGM、やめる、ヒント、進捗を含む |
| フォニックス説明 | `.phonics-intro-stage` | 固定1400×1050を`--stage-scale`で縮小 | 「やめる」は問題画面と同じ表示倍率 |
| フォニックス動画 | `.phonics-youtube-stage` | 固定1400×1050を`--stage-scale`で縮小 | 動画部分にはさらに局所のscale(.8) |
| コレクション一覧 | `.collection-stage` | 固定1400×1050を`--collection-scale`で縮小 | カテゴリや左右矢印は表示状態を伴う |
| コレクション詳細 | `.collection-detail-stage` | 可変4:3、固定pxと相対長混在 | 一覧と詳細で戻る、残り時間、ナビの表示比率に差が生じうる |
| 結果 | `.result-stage` | 可変4:3＋vw/vh/固定px | アクションボタン・ラベルに複数基準 |
| 確認・管理・プロフィールのオーバーレイ | 複数 | viewport、親画面、clampの混在 | 画面全体の縮小を無条件に適用しない |

## 統一する設計契約

1. **ゲーム描画領域の正規化座標は1400×1050**。各画面の4:3ステージは、論理座標`(x,y,w,h)`をこのキャンバス内で定義する。ステージの見た目は`s = min(innerWidth/1400, innerHeight/1050)`で等倍縮小・中央揃えする。画面内の共通操作UIは同じスケール空間に置く。必要な場合は論理ピクセルから`s`を乗じた値で計算する。
2. **物理的なクリック領域と視覚表示寸法を別々に測る**。比較対象は`getBoundingClientRect()`の幅・高さ・位置で、CSS指定値だけでは合格にしない。アイコン文字はフォントレンダリング差も記録する。
3. **オーバーレイは分類する**。ステージに従属するゲーム内確認・報酬はステージ座標。保護者設定・PIN・プレイヤー管理など端末横断の操作用ダイアログはviewport座標を維持し、タッチ領域やアクセシビリティに配慮する。双方を同じクラスに無差別統一しない。
4. **配置を守る**。トップBGMの右下、問題BGMのヒント左、戻る・やめる等の既存位置と前後関係を保持。元画面の端からの距離は基準キャンバスの論理座標として整理する。
5. **既存のSafari保護を変えない**。`isNormalViewport`の異常ズーム判定、二重requestAnimationFrameのスケジュール、`sizePlayStage`による安定時更新と`visualViewport`監視を維持する。ズーム状態ではステージ倍率を書き換えない。
6. **共通UIの見た目とデータを分離**。表示サイズ修正にあたり、BGMのON/OFF・保存キー、学習進行、プロフィール、コレクション保存には触れない。

## 初期の可視サイズ要件

- BGM：トップと問題画面の同一viewport内で幅・高さ差 **0.5 CSS px未満**。比較は基準サイズ1400×1050だけに限定しない。
- 「やめる」：問題・フォニックス説明・動画で現状の一致を維持。
- 戻る、コレクション終了、残り時間、左右矢印：画面間で**同じ意味・意図されたサイズ**の場合にのみ一致を要求。サイズが仕様上異なるものは検証対象に含めるが自動で同寸にはしない。
- 操作ターゲット：ステージ縮小時にも必要なタップ領域を確保すること。現在の計測値を正本として変更差分を見える化する。

## 検証方法

- PR #159の`tests/ui-scale-audit.cjs`を利用し、1400×1050 / 1024×768 / 768×1024 / 1280×720で全画面の実寸をJSON＋Markdown保存。
- 合否アサーションとは別に診断レポートを保持。未表示・未初期化の要素は`hidden`/`missing`で明示し、測れていない項目をPASS扱いしない。
- コレクションのカテゴリとナビは実操作で初期化して測定する。単なる`.active`切替による構造計測は「実表示保証なし」と注記する。
- Playwright/ChromiumはCIの基準検証。最終受け入れはiPad Safari PWAでトップ→学習→コレクション→トップを往復し、縦横向き、復帰後のズーム、タップ対象と文字・枠の見え方を確認する。

## 修正PRの推奨分割（第3段階）

| 順序 | テーマ | 変更境界 | 検証 |
|---|---|---|---|
| 1 | トップBGMの表示倍率統一 | トップBGMの視覚寸法計算、必要最小限のCSS | 複数viewportで実寸差0.5px未満＋BGM操作テスト |
| 2 | トップ固定px操作UIの体系整理 | リロード、歯車、保護者、プレイヤー切替のスケール基準。意図的なサイズ差は維持 | レイアウトとタップ領域の実寸差分 |
| 3 | モード選択・結果・詳細の可変ステージ座標移行 | 画面単位で別PR。画像、ボタン位置を維持 | 画面ごとの比較＋回帰 |
| 4 | コレクション一覧／詳細の操作UI基準確認 | 戻る、終了、時間、タブ、矢印（デザイン上の差は許容） | 実画面遷移での寸法と押下判定 |
| 5 | 共通UI再発防止 | 横断テストと計測未達チェックをCIへ組み込む | 縦横・iPad相当・横長・基準の4viewport |

**各PRは1テーマ。ユーザー影響のある変更では最新mainに対してパッチ版番号を+1し、Preview検証・承認後にマージする。** 現行のステージスケール更新ロジックを一括置換しない。

## 第2段階の完了条件と未解決点

この文書はコード監査からの設計契約。ブラウザ実測で見つかったBGM差を記載しているが、コレクション詳細など全共通UIの表示不具合を確定したものではない。次の実装では差分レポートと画面遷移の実測結果に基づいて優先度を確定する。

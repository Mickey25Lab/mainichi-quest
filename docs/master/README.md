# マイクエ正本ガイド

最終更新：2026-10-23

このフォルダは、マイクエを継続開発するときの**プロダクト判断の正本**である。
過去チャットの記憶ではなく、まずこの案内と該当する正本を読む。

## 最初に読む順番

1. この文書
2. `ABCマスター.md` — 今どこにいて、次に何を目指すか
3. `マイクエ_改善バックログ.md` — 未解決の課題と優先順位
4. 変更対象に応じて、次の正本を読む

| 変更対象 | 正本 | ここに書くこと |
| --- | --- | --- |
| 画面、遊び方、操作、演出 | `マイクエ_現行仕様.md` | 現在のアプリがどう動くべきか |
| 発見、なかよし、進化、ポイント、報酬 | `報酬体系マスタ.md` | 報酬・進行のルール |
| 車種、レアリティ、表示順、素材名 | `車種マスタ.md` | 20車種の属性と固定ID |
| 中長期の狙い、外部家庭テスト、開発基盤 | `ABCマスター.md` | ロードマップと大きな判断 |
| 未着手課題、調査、改善候補 | `マイクエ_改善バックログ.md` | 次に取り組む候補 |

## 正本の使い分け

- 同じ内容を複数のMDへコピーしない。詳細は担当する正本にだけ書き、他の文書からリンクする。
- 現在の挙動を変えるPRでは、対応する正本を同じPRで更新する。
- まだ決まっていないことは、現在仕様へ書かず、バックログまたはABCマスターの将来候補として扱う。
- コードと正本が食い違う場合、勝手にコードを正しい仕様として追認しない。意図を確認し、必要なら決定記録を残す。

## 更新の責任

CodexはPR作成時に正本更新の必要性を確認し、更新する場合は理由と変更箇所を報告する。
学習内容、報酬体系、世界観、ブランド、事業判断はKimiが決める。Codexは選択肢・影響・根拠を分かりやすく提示する。

## この正本整備の進め方

2026-10-23時点では、2026-10-04以降に増えたフォニックス、レベル、エネルギーカプセル、親設定などを順に実装と照合している。

1. 正本の入口・役割・ロードマップを揃える（このPR）
2. 現行仕様へ新しい画面・学習モード・保存データを反映する
3. 報酬・車種・保存データを実装と照合し、未確定事項を明記する

この期間中も、未照合の内容を推測で正本へ書かない。

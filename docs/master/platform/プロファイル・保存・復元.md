# プロファイル・保存・復元

状態：実装済み  
コード参照先：`dist/scripts/profile-storage.js`  
監査記録：[`../../child-profile-phase1-storage-audit.md`](../../child-profile-phase1-storage-audit.md)

子どもごとにプロフィールを分け、報酬進捗、コレクション、ポイント、レベル、カプセル、学習設定、日次ミッションを保存する。BGM設定など端末共通の設定と、子ども固有データは区別する。

保存形式の変更では、既存データを保つ移行と復元確認を必須とする。子どもデータを削除・初期化する変更は、明示承認なしに実行しない。保存キー・旧キー・移行上のリスクは監査記録を正とし、この文書に二重転記しない。

## プレイ単位の確定・中断（ワークストリーム2／PR2）

通常の問題演習では、プレイ開始時にプロフィール別の報酬進捗・コレクション段階・直近車種履歴をメモリへ退避し、プレイ中の更新は永続保存しない。正解後の発見・なかよし・エネルギー・進化の演出はプレイ中の作業状態を使う。

- 最終問題と必要な復習が完了し、結果画面へ進む時点で進捗を一度確定する。ポイント・レベル計算は既存の `commitRewardProgressWithPoints` を使う。
- 確定まで獲得履歴の追記もメモリに保留する。正式確定後に追記する。
- プレイ途中で「やめる」を確定した場合は、作業状態を破棄してプレイ開始前の状態に戻す。
- 途中でタブを閉じたり再読み込みした場合は、作業状態はメモリにしかないため保存されず、以前の正式保存状態が読み込まれる。
- 既存のプロフィール・保存キー・保存形式は変更しない。既存の蓄積データを初期化・消去しない。
- 異なるプロフィールへの確定を禁止するため、プレイ開始時のプロフィールIDと確定時のIDが異なる場合は破棄する。
- ベストタイムと日次ミッション完了回数は、従来どおり完走後だけ保存する。
- フォニックス動画後の報酬選択や、結果画面以降のコレクション内アイテム操作はこの通常問題プレイの仮保存期間に含めない。

実装参照：`dist/app.js` の `beginRoundTransaction`・`commitRoundTransaction`・`discardRoundTransaction`。検証参照：`tests/round-transaction.test.cjs`。

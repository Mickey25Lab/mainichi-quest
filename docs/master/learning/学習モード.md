# 学習モード

最終更新：2026-10-24  
状態：実装済み

## 共通ルール

- 各モードの初回ラウンドを完了すると、復習対象がある計算モードは復習へ進み、それ以外は結果画面に進む。問題数はモードごとに異なる。
- **計算モード**（わり算、わり算ひっ算、かけ算ひっ算）は、初回ラウンドで不正解・ヒント使用・答え表示があった問題を最後に復習する。復習は、報酬・エネルギー・タイムボーナス・連続正解へ影響しない。
- **すうじあつめ・かずかぞえ**は復習ラウンドを作らない。不正解後も同じ問題でやり直せるが、10問の初回ラウンド終了後は結果画面へ進む。
- ヒント・答え表示を使った問題、または不正解を含む問題は、自力正解の報酬条件に影響する。具体的な報酬量は [`../game/報酬体系.md`](../game/報酬体系.md) を正とする。
- 保護者はモードごとの1日目標回数と、エネルギーのたまりやすさを設定できる。設定値は子どもプロフィールごとに保存する。
- タイムボーナスの対象は計算モードの一部だけで、すうじあつめ・かずかぞえ・フォニックスは対象外である。詳細は [`../game/報酬体系.md`](../game/報酬体系.md) を正とする。

## 日次ミッションの最終完了判定（ワークストリーム2・PR3）

- プロフィール別・JST日付別・有効な目標回数別に、プレイ前とプレイ完了時の残り回数を判定する。
- **今回の1回で** 全有効モードの残り回数が0になる場合だけ「本日最後のミッションを完了した」という内部判定を成立させる。すでに全完了の状態での自由プレイ、対象外モード、目標回数0件は対象外。
- 通常学習は全問題（必要な復習を含む）の完走後、フォニックスは従来の日次完了計上地点で判定する。途中終了は計上しない。
- プレイ開始時のプロフィールとJST日付が完了時と異なる場合は、そのプレイを当日ミッションに計上しない。翌日にまたがったプレイを翌日の初回達成として誤認しない。
- 判定結果は内部メモリのみ。保存済みの日次達成回数以外に新しい永続フラグを作らず、受け取り画面・報酬・終了導線は本PRでは変更しない。

コード参照：`dist/app.js` の `beginDailyMissionAttempt`、`dailyMissionCompletionTransition`、`completeDailyMissionRound`。テスト：`tests/daily-final-mission.test.cjs`。

### 保護者設定変更による全クエスト達成

- 日次の「すべて達成済みか」は、その時点の保護者設定・達成回数をもとに随時計算する。親が目標を追加・増加すれば再び未達成になり、減少・OFFにすればプレイをしなくても全達成になり得る。
- 設定変更それ自体は「子どもの最後の1プレイ完了」イベントを発生させない。新しい必要回数が残った場合、実際にその回数を完了すれば内部最終達成として検知する。
- 達成した回数は目標回数の増減によって消去しない。全モード目標0回は「未設定」であり達成イベントの対象外。
- 新規追加モードは目標0回を原則とし、既存設定の未指定値が勝手に有効化されないことを別途確認する。
- 報酬の受領可能性は次PRの受領処理で現在の全達成状態から判定する。親が目標を減らして全達成した場合も当日の受領対象に含める。

### 次PRで実装する報酬仕様（PR3では付与しない）

- 正式名称：**クエスト達成ボーナス**。当日の有効なクエストを全達成すると、子どもが**育てたい車種を1台選ぶ**。報酬の種類は選ばない。選択車種がハートを集める段階なら**ハート5個**（ハート5個分の進行）、エネルギーを集める段階なら **「10＋達成時レベル×5」のエネルギー** を自動付与する。既存のフォニックス育成時と同じ、車種の成長段階に応じた報酬判定とする。
- **プロフィールごと・JST日付ごとに1日1回のみ。翌日への持ち越しはなし。** 前日分を翌日に受け取れず、同日中に親が目標を増減しても二重付与しない。
- 車種選択後、成長段階に応じたハートまたはエネルギーのチャージを行う。受領・チャージの二重適用を防止し、確定した報酬量と受領済み日付を保存する。レベル変化による同日分の再計算はしない。
- タイムボーナスは未割り当て分を翌日に持ち越す。クエスト達成ボーナスとは受取画面／チャージ処理を共通化するが、有効期限と獲得条件は分ける。
- いずれの報酬も本PR3では発生・付与させない。報酬選択・保存・画面処理は次PR4以降の対象。

## クエスト達成ボーナス（ワークストリーム2・PR4）

- 今日の有効なクエストを全達成したプロフィールに、**JST当日限り・1日1回**のボーナス受取機会を設ける。未設定（目標0件）は対象外。親の目標回数変更で全達成に変わった場合も対象。
- 子どもが選ぶのは**育てる車種1台**。報酬の種類は選ばず、選択車種がハート段階ならハート5個（上限5）、エネルギー段階なら `10 + 全達成時のプレイヤーレベル × 5` を加算する。レベルは既存のポイント台帳に基づき、クエスト全達成時点で固定する。親の設定変更だけで全達成した場合は、次に選択画面を開いた時点のレベルで固定する。
- チャージ・進化処理は既存のフォニックス育成にある `applyPhonicsRewardGrowth` と `applyEnergyGain`、`commitAcquisition` を再利用。通常のフォニックス報酬の数量・ランダム抽選には影響させない。
- クエスト達成ボーナスの受取は**選んだ車種への進行保存と同時に**プロフィール固有の最終受取日として書き込み、二重付与を禁止。翌日への繰越はない。
- **モード選択画面にアクセスした時**、全達成なら既存の「全部クリア／よくがんばったね」のやめ時表示を先に見せる。その表示から「のりものをそだてる」を押して、車種選択・チャージへ続く。起動時に直接チャージ画面へ飛ばしたり、別のお祝い画面を新設したりしない。既存の完了パネルはモード選択画面の独立したポップアップレイヤーとして配置し、1400×1050固定キャンバスから切り離す。iPadの画面倍率でもパネルと続行ボタンを見切れさせない。途中でブラウザを閉じた場合は受領済みとせず、当日なら再開可能。
- **タイムエネルギー**の未割当残高・翌日への繰越および共通の30秒割当画面への統合は次PR以降の対象。

実装：`dist/app.js` の `questBonusAvailable`、`openPhonicsRewardSelection({ quest: true })`、`applyPhonicsRewardGrowth`、`dist/scripts/profile-storage.js` の `commitRewardProgressWithPoints`。保存テスト：`tests/profile-storage.test.cjs`。

### 保護者設定：全モードを一括0回にする

- 「おうちの人へ」に「すべてのモードを0回にする」ボタンを設ける。**選択中の子どもプロフィールの全モード**を一括して0回（OFF）にする。
- ボタン押下時は画面上の編集用設定だけ変更する。「保存する」で確定、「保存せずに戻る」で破棄する。他の子どもの設定・学習済み回数・育成データには影響しない。
- 全モード0回はクエスト未設定であり、クエスト達成ボーナスは発生しない。

### クエスト達成ボーナス 表示・割当調整

- ガレージの見出し「クエスト達成！ そだてるのりものをえらぼう！」は1行表示とし、「達成」に「たっせい」のルビを付ける。
- エネルギー量は **8＋全達成時レベル×2**（Lv1=10、Lv5=18）に変更。ハート段階は引き続き**ハート5個**で固定する。
- 車種選択後の確認には「ハート +5」または「エネルギー +N」を車種の段階に応じて表示する。子どもには報酬種類を選ばせない。
- 既存の「今日のミッション全部クリア！」表示は可読性重視の普通のゴシック体に変更する。
- ガレージに入った時点から **30秒** で車種を決める。残り表示はコレクションと同じ右下UIで30→20→10秒、最後は9→0秒の1秒刻み。確定しないまま時間切れなら、発見済みの車種からランダムに1台選んで報酬をチャージし、同じ日次受領記録を保存する。フォニックス側のルーレット・報酬量は変更しない。

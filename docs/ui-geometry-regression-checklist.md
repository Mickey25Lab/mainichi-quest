# UI倍率の回帰防止とiPad Safari確認

## CIで自動確認すること
- 既存の `tests/ui-scale-audit.cjs` は全画面の構造計測レポート。非表示DOMを一時表示する測定は、実画面の合格判定には使わない。
- `tests/ui-interaction-geometry.test.cjs` は4 viewport（1400×1050、1024×768、768×1024、1280×720）で実際にトップからコレクションへ操作し、可視のゲーム領域が4:3で画面内に収まり、代表操作ボタンが20 CSS px以上あることを確認する。これは最低限の退行検知であり、iPadの使いやすさを保証する閾値ではない。
- 失敗時はCIを赤にし、`audit-results/ui-scale/interaction-geometry.json` で計測位置と寸法を確認する。
- 将来、問題画面・フォニックス・詳細画面を実操作で起動する安定したテスト用経路が確保できたら、個別テストとして追加する。現時点でそれらを実操作検証したとは扱わない。

## iPad Safari/PWA 目視確認
大きさに影響するPRで必要な画面に絞って以下を確認する（チェック内容と結果をPRに記録する）。

1. Safariブラウザとホーム画面PWAで起動し、トップ→モード選択→学習→結果→トップ、およびトップ→コレクション一覧→車種別詳細→トップを往復する。
2. 横向きと縦向きで、主要ボタンの大きさ・画面の端からの距離・文字の視認性・タップ領域を確認する。
3. 画面回転、ホームへの移動と復帰、アプリ切替の後、意図しない拡大・縮小がないか確認する。
4. ゲームの「やめる」、コレクション終了確認、フォニックス報酬選択など、変更したポップアップがゲーム領域を正しく覆い、ボタンが操作できることを確認する。
5. 結果を「Safari/PWA、向き、確認画面、OK/NG、スクリーンショットまたは再現手順」でPRに記録する。未実施は「未実施」と記す。

Playwright Chromiumの成功はSafari実機の成功を意味しない。Safariの異常ズーム防止ロジックやプレイヤーデータは本PRで変更しない。

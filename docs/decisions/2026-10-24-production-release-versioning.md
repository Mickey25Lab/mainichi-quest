# 2026-10-24 本番バージョン管理の決定

## 背景
ブランチ保護により、従来の「mainへの直接pushでpatchを増やす」ワークフローが失敗した。専用PR案は承認回数が増えるため採用しない。

## 決定
- 通常の機能修正は1テーマ1PR・1回のマージ承認を維持する。
- 前回の本番成功リリースをGitタグ `mq-prod-v<major>.<minor>.<patch>` で記録する。初期値はソースの `0.3.52`。
- 新規 `dist/` 変更を含む本番公開時はpatchを1加算する。変更なし・同一コミットの再実行では維持する。
- 公開直前に、公開用 `dist/app.js` のVersion表示へバージョン、Actions実行番号・試行番号のBuild、Gitコミット短縮SHAを埋め込む。`dist/release-meta.json` に詳細を記録する。
- 成功したGitHub Pagesデプロイ後、当該コミットを指すリリースタグを作成する。mainにはバージョン用の追加コミットをしない。
- PR Previewは既存の挙動を維持し、本番用加工は適用しない。

## 留意点・見直し条件
デプロイ成功後のタグ記録に失敗した場合は失敗として調査し、次回の誤採番を防ぐ。Gitタグ書き込み権限が制限された場合は、保護ルールを迂回せず別の成功リリース台帳を検討する。公開成果物のバージョンはmain上のソース文字列と異なり得るため、本番の正本は `release-meta.json` とタグに置く。
